# ADR 0031: Internal API TLS

**Status:** Accepted
**Date:** 2026-11-19

## Context

After Redis, Postgres ([ADR 0029](./0029-postgres-tls.mdx)), and object storage ([ADR 0030](./0030-object-storage-tls.mdx)), two hops to the API still crossed the shared `dokploy-network` in plaintext:

- **Traefik to the API.** Traefik terminates the public HTTPS with Let's Encrypt, then forwarded every request (browsers, the mobile app, the extension, AI assistants) to `http://…:26631`. Those requests carry access tokens, cookies, and user data.
- **The webapp's server side to the API.** Server rendering and the BFF routes called `http://${prefix}-api:26631`, with access and refresh tokens and the webapp's OAuth client secret on `/oauth2/token`.

`dokploy-network` joins every stack on a Dokploy host. Docker gives containers `NET_RAW` by default, so a compromised neighbor container could intercept traffic on that bridge.

## Decision

1. **The API serves HTTPS only.** One listener, `API_PORT` `26642`, TLS 1.3, WebSocket sync included. Fastify creates it with its own `https` option (`buildServer()` and `loadApiTlsOptions()` in `apps/api/src/lib/platform/api-tls.ts`), so Fastify's timeouts, shutdown, and `@fastify/websocket` work as on a plain server. The API does not start without its certificate and key. There is no plain HTTP port: the container healthcheck calls `https://127.0.0.1:26642/health/live` and verifies the API CA. Local development uses the same listener on loopback: Portless forwards to it with `--upstream https`, the webapp's server side calls it with the dev CA, and a phone reaches it through `tailscale serve` (`pnpm run dev:mobile-api`), which has a public certificate for the tailnet name. The first version kept HTTP `26631` for the healthcheck and served HTTPS from a second Node server that shared `fastify.routing`. That left a plaintext port on the shared network and a second code path, so it was replaced.
2. **Its own CA.** `stack-secrets` issues a private API CA (20 years) and a certificate (10 years) for `api`, `${prefix}-api`, `localhost`, and `127.0.0.1`, reissued 90 days before expiry, on a name change, or when the CA changed. The API image runs as uid 1001 without a root step, so the job makes the key directory and files owned by that user. Volumes: `api-tls-ca` (the job), `api-tls-server` (api), `api-tls-client` (webapp, the transport job, and the api for its healthcheck; the CA certificate only).
3. **Traefik forwards over HTTPS through published transports.** Verifying a private CA needs a Traefik `serversTransport` with `rootCAs`. Docker labels can only reference a transport defined by the file provider (or Kubernetes), not define one. Dokploy runs Traefik with a file provider that watches `/etc/dokploy/traefik/dynamic`; another Traefik names its folder in `BONDERY_INFRA_TRAEFIK_DYNAMIC_DIR` (Coolify: `/data/coolify/proxy/dynamic`). The one-shot `traefik-transport` service writes one file per service there, `${prefix}-api-transport.yml` and `${prefix}-storage-transport.yml`, each with its CA inline and `serverName: ${prefix}-<service>`. The `api` labels forward to `26642` and the `seaweedfs-s3` labels to `8443`, both with `server.scheme=https` and their transport.
4. **The public storage route takes reads only, without cookies.** Better Auth sets its session cookie on the parent domain (`crossSubDomainCookies`), so browsers send it with every image request to the storage domain. The storage router matches only `GET`, `HEAD`, and `OPTIONS`, and a headers middleware drops `Cookie` and `Authorization`: public reads never need them, and SeaweedFS never sees a session token.
5. **That job is kept small, because it writes into Traefik's configuration.** The folder also holds `acme.json` (every domain's Let's Encrypt keys) and Dokploy's own routes, so whatever writes there could change routing for every stack on the host. The job is not the API image and its dependency tree: a pinned `busybox` image runs `deploy/bondery/traefik/publish-transports.sh` from git, with `network_mode: none`, `cap_drop: ALL`, `no-new-privileges`, and a read-only root filesystem. The script validates the prefix (`[a-z0-9-]`), writes only its own files (the services are allow-listed) through a staging file and a rename, and rewrites a file only when its content changed. The folder is bound with `create_host_path: false`, so a host without that folder fails loudly instead of growing a stray one; `docker-compose.override.yml.example` turns the job off for hosts without Traefik and binds every stack port to `127.0.0.1`, for Caddy or nginx on the same host (`deploy/bondery/proxy/`).
6. **The webapp trusts the CA process-wide, at startup.** Every server-side call goes through Node's TLS stack, but not one place: Next.js wraps `fetch` and replaces undici dispatchers, and jose fetches the JWKS with its own fetch. `instrumentation.ts` runs before the server takes requests, and the proxy runs in the same Node process (Next.js 16 runs it on Node only). There, `tls.setDefaultCACertificates()` adds the CA to the certificates Node already trusts. `NODE_EXTRA_CA_CERTS` does the same, but ignores a missing file with only a warning; the webapp instead refuses to start when the file cannot be read, or is set for an `http://` URL.
7. **Compose owns the settings.** The webapp's internal URL and CA path, the API's certificate paths, port, and Traefik labels, and the transport job's hardening are fixed in the stack files. `check-compose-api-tls.mjs` fails on any drift in the three stack variants.
8. **Expiry is visible.** The API logs the days left on its certificate at boot, and the daily `tls-certificate-check` job covers it with the Postgres and storage certificates.

## Findings that shaped the details

| Finding | Consequence |
|---|---|
| Fastify 5.12.8 with the `https` option creates a Node `https.Server`, applies its own timeouts to it, and `@fastify/websocket` upgrades on it (a unit test opens a `wss` connection) | One listener, no second server and no upgrade forwarding |
| Better Auth's `mcp()` plugin rejects an `http://` resource that is not loopback. The old phone setup used `http://<tailscale-ip>:26631`, which needed a mapping to loopback | The phone uses `https://<machine>.<tailnet>.ts.net:26642`; the mapping is gone |
| Portless (`--upstream https`) and `tailscale serve` (`https+insecure://`) connect to the API over TLS without checking its certificate | Acceptable only because both hops stay on loopback; the dev API binds `127.0.0.1` by default |
| Docker Desktop for Windows creates a missing bind-mount folder given as a Windows path, even with `create_host_path: false`; a Linux path fails with `bind source path does not exist` | The transport job fails loudly on Linux hosts (Dokploy, Coolify); on Docker Desktop the check is weaker |
| On Node 26, `tls.setDefaultCACertificates([...getCACertificates("default"), ca])` makes the global `fetch` accept a server it refused before, and keeps the 120 built-in roots | One startup call covers Next.js fetch, the BFF, the OAuth token exchange, and the JWKS fetch |
| Traefik 3.6.25 (Dokploy's default) reads subfolders of the file provider folder, but only watches the top folder and its files. It skips files with other extensions (`acme.json`, `.pem`, the staging `.tmp`) | The transport file goes in the top folder; a subfolder would be missed on the first deploy |
| Traefik 3.6.25 accepts the CA inline in `rootCAs`, refuses a backend signed by another CA (`x509: certificate signed by unknown authority`, 500), and applies a rewritten file within seconds | No separate `.pem` file; a wrong or stale CA fails closed; rerunning the job repairs a tampered file |
| Better Auth's session cookie has `Domain=<parent domain>`, so it reached the storage domain and crossed the HTTP hop from Traefik to SeaweedFS | The storage route moved to HTTPS with its own transport, and drops `Cookie` and `Authorization` |
| On Docker Desktop for Windows, a folder bind-mounted from the host does not deliver file events to Traefik, so rewrites are missed | Local tests share a named volume (a Linux filesystem, like a Dokploy host) between the job and Traefik |
| A module named `*.node.ts` cannot be imported by Node's own resolver in tests (`.node` is the native addon extension) | The webapp module is `internalApiTls.server.ts`, the convention for Node-only webapp modules |

## Not covered

- **Traefik to the webapp** stays HTTP on port `26632`. Next.js's standalone server has no HTTPS option without a custom server. The same transport mechanism applies once it does.
- **Client certificates.** The HTTPS port accepts any client that can open a TLS connection; callers authenticate with tokens and the OAuth client secret. A container on `dokploy-network` can still call the API directly and set `X-Forwarded-For`, which the API trusts (`trustProxy: true`). Client certificates for Traefik and the webapp would close that; they are a separate change.
- **Platforms that forward plain HTTP to a container port** (a Dokploy "Docker Image" application, most PaaS) cannot run the API image on its own any more. The Compose stack, or a proxy that connects over HTTPS and trusts the CA, can.

## Rollout

One release. On the first deploy the `traefik-transport` job writes the transport before the API starts, and the API waits for it. The release smoke checks that the published transport's CA verifies the API's HTTPS listener under its `serverName`, that the API started the listener, that a webapp route which proxies to the API succeeds, that the listener refuses plaintext and clients without the API CA, that the HTTPS healthcheck reports healthy, and that nothing listens on `26631`. Rollback is the previous release: Traefik forwards to `26631` again, and the leftover transport file is unused.
