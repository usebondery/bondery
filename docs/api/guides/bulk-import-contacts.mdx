## Prerequisites

Use the import endpoints when you have contact data outside LinkedIn or Instagram exports. A vCard (`.vcf`) export from another app is the simplest source, or you can build contacts programmatically.

The flow is always **parse, preview, commit**. Parsing validates and normalizes rows. Committing writes the selected contacts to the account.

You need:

- A [full-access API key](../authentication.mdx) or a session token
- Contacts shaped like the API import schemas (vCard is the simplest starting point)

All paths below are relative to your API origin. `https://api.usebondery.com` is the hosted origin.

## vCard import

<Steps>
<Step>

### Parse the file

`POST /contacts/import/vcard/parse`

Send the vCard file as `multipart/form-data`. The route reads every uploaded file part, so the field name is free. The response lists parsed contacts with validation metadata, so you can preview before writing anything.

<PlatformCode
  posix={`curl -X POST "https://api.usebondery.com/contacts/import/vcard/parse" \\
  -H "Authorization: Bearer bondery_key_<keyId>_<secret>" \\
  -F "file=@contacts.vcf"`}
  windows={`curl.exe -X POST "https://api.usebondery.com/contacts/import/vcard/parse" -H "Authorization: Bearer bondery_key_<keyId>_<secret>" -F "file=@contacts.vcf"`}
/>

</Step>
<Step>

### Review the preview

Check each contact in the response. Drop invalid rows or duplicates before commit. The webapp import UI follows the same parse and commit pattern.

</Step>
<Step>

### Commit selected contacts

`POST /contacts/import/vcard/commit`

Send the contacts you want to import in the request body. Each commit accepts up to **25** contacts per request, so batch larger imports in chunks.

<PlatformCode
  posix={`curl -X POST "https://api.usebondery.com/contacts/import/vcard/commit" \\
  -H "Authorization: Bearer bondery_key_<keyId>_<secret>" \\
  -H "Content-Type: application/json" \\
  -d '{"contacts": [/* contacts from the parse response */]}'`}
  windows={`curl.exe -X POST "https://api.usebondery.com/contacts/import/vcard/commit" -H "Authorization: Bearer bondery_key_<keyId>_<secret>" -H "Content-Type: application/json" -d '{"contacts": [/* contacts from the parse response */]}'`}
/>

Repeat until all batches are committed.

</Step>
</Steps>

## Platform exports (LinkedIn / Instagram)

For native platform ZIP exports, use the dedicated endpoints instead of vCard:

| Platform | Parse | Commit |
|---|---|---|
| LinkedIn | `POST /contacts/import/linkedin/parse` | `POST /contacts/import/linkedin/commit` |
| Instagram | `POST /contacts/import/instagram/parse` | `POST /contacts/import/instagram/commit` |

See the [Import guide](../../bondery/import.mdx) for what each export contains and how the webapp presents previews.

## Create contacts one at a time

For small scripts, `POST /contacts` creates a single contact without the import pipeline. Prefer parse and commit when you have many rows, or when you need the same validation as the webapp importer.

## Errors

Import failures return the standard API error envelope. Look up `error.code` in [Error codes](/docs/api/errors). Common cases include `validation_error`, `auth_required`, and `rate_limit_exceeded`.
