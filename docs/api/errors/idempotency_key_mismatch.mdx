## When this happens

The same `Idempotency-Key` was sent again with a different method, path, query string, or raw body. JSON key order is part of the body.

## What your integration should do

Send a new `Idempotency-Key` for the new request. Do not reuse the old key. To replay the first response, send the original request bytes again.

## What end users should see

Show `common.errors.api.idempotency_key_mismatch`.

## Response fields

| Property | Value |
|----------|-------|
| **Type** | `invalid_request_error` |
| **HTTP status** | 422 |
| **code** | `idempotency_key_mismatch` |
| **doc_url** | `/docs/api/errors/idempotency_key_mismatch` |

The API `message` field is for developers debugging in logs. Product UI must key off `code` (and `details` for validation). `agent_message` states the same failure plus how to fix the call, for an AI agent.
