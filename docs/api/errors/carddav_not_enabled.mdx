## When this happens

You call a CardDAV management route on a server where the CardDAV switch is off. `GET /me/carddav` does not fail: it answers `enabled: false`.

## What your integration should do

Read `enabled` from `GET /me/carddav` and hide device sync when it is false. Do not retry.

## What end users should see

Translate with `common.errors.api.carddav_not_enabled`. Never surface the raw API `message`.

## Response fields

| Property | Value |
|----------|-------|
| **Type** | `not_found_error` |
| **HTTP status** | 404 |
| **code** | `carddav_not_enabled` |
| **doc_url** | `/docs/api/errors/carddav_not_enabled` |

The API `message` field is for developers debugging in logs. Product UI must key off `code` (and `details` for validation). `agent_message` states the same failure plus how to fix the call, for an AI agent.
