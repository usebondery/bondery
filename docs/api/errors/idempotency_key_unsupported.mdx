## When this happens

The client sent `Idempotency-Key` to a route that sets `idempotency: false`. `POST /chat` is the exempt route because the reply is a stream.

## What your integration should do

Remove the `Idempotency-Key` header. Retry the call. Do not expect a stored replay from this route.

## What end users should see

Show `common.errors.api.idempotency_key_unsupported`.

## Response fields

| Property | Value |
|----------|-------|
| **Type** | `invalid_request_error` |
| **HTTP status** | 400 |
| **code** | `idempotency_key_unsupported` |
| **doc_url** | `/docs/api/errors/idempotency_key_unsupported` |

The API `message` field is for developers debugging in logs. Product UI must key off `code` (and `details` for validation). `agent_message` states the same failure plus how to fix the call, for an AI agent.
