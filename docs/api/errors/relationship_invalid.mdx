title: relationship_invalid
description: The relationship payload failed validation. Send two known contact ids and a relationship type, and never send the same id at both ends of it.
last_updated: 2026-07-28
---

## When this happens

A domain rule blocked the operation after validation. Affects **Relationships** operations.

## What your integration should do

Verify both contact ids, relationship type, and that you are not relating a contact to itself.

## What end users should see

Translate with `common.errors.api.relationship_invalid` when a string exists; otherwise map by domain prefix. Never surface the raw API `message`.

## Response fields

| Property | Value |
|----------|-------|
| **Type** | `invalid_request_error` |
| **HTTP status** | 400 |
| **code** | `relationship_invalid` |
| **doc_url** | `/docs/api/errors/relationship_invalid` |

The API `message` field is for developers debugging in logs. Product UI must key off `code` (and `details` for validation). `agent_message` states the same failure plus how to fix the call, for an AI agent.
