## When this happens

Redis-backed rate limiter blocked the request.

## What your integration should do

Read `RateLimit` and `RateLimit-Policy` on each limited response. `r` is the remaining requests. `t` is the seconds until reset. Slow down while `r` is low.

On 429, read `Retry-After`. It equals `t` and `error.retry_after`. Wait that many seconds. Then retry the same call.

```http
RateLimit-Policy: "default";q=300;w=60
RateLimit: "default";r=12;t=47
```

`q` is the quota. `w` is the window in seconds. A route can send a different policy name, such as `ai` or `export`.

`Retry-After` is present on 429 only.

## What end users should see

Ask the user to wait (`common.errors.api.rate` or rate-limit copy).

## Response fields

| Property | Value |
|----------|-------|
| **Type** | `rate_limit_error` |
| **HTTP status** | 429 |
| **code** | `rate_limit_exceeded` |
| **doc_url** | `/docs/api/errors/rate_limit_exceeded` |

The API `message` field is for developers debugging in logs. Product UI must key off `code` (and `details` for validation). `agent_message` states the same failure plus how to fix the call, for an AI agent.
