You need a server that meets [Requirements](./requirements.mdx), Docker with Compose v2.38 or newer, and hostnames for the API and the web app. Read [Configuration](./configuration.mdx) before you start, because the stack does not boot without its secrets.

<Steps>
<Step>

## Prepare environment

<PlatformCode
  posix={`docker network create dokploy-network   # once, when using Traefik / Dokploy

cd deploy/bondery
cp .env.example .env`}
  windows={`docker network create dokploy-network   # once, when using Traefik / Dokploy

cd deploy/bondery
Copy-Item .env.example .env`}
/>

Fill domains and secrets — see [Configuration](./configuration.mdx) for the full variable list.

</Step>
<Step>

## Start services

```bash
docker compose up -d
```

**Without Traefik** (laptop smoke test):

<PlatformCode
  posix={`cp docker-compose.override.yml.example docker-compose.override.yml
docker compose up -d
curl -sf http://localhost:26631/health/live
curl -sf http://localhost:26632/health/live`}
  windows={`Copy-Item docker-compose.override.yml.example docker-compose.override.yml
docker compose up -d
curl.exe -sf http://localhost:26631/health/live
curl.exe -sf http://localhost:26632/health/live`}
/>
</Step>
<Step>

## First-boot database

`docker compose up` runs `api` `pre_start` init containers before the main API container starts — they apply `prisma migrate deploy`, `functions.sql`, OAuth client provisioning, platform admin promotion, and SeaweedFS bucket creation. No manual step needed on first boot.

`pre_start` is skipped on ordinary `api` restarts when the init definition is unchanged. It runs again when `api` is recreated (new image, config change, or explicit recreate).

Requires Docker Compose **v2.38+** (`pre_start` support). Check with `docker compose version`.

</Step>
<Step>

## Verify

<PlatformCode
  posix={`curl -sf https://api.example.com/health/ready
curl -sf https://api.example.com/oauth-providers
curl -sf https://app.example.com/health/ready
curl -sf https://app.example.com/api/health/ready`}
  windows={`curl.exe -sf https://api.example.com/health/ready
curl.exe -sf https://api.example.com/oauth-providers
curl.exe -sf https://app.example.com/health/ready
curl.exe -sf https://app.example.com/api/health/ready`}
/>

GitHub and LinkedIn sign-in are optional. Leave both `BONDERY_PRIVATE_AUTH_GITHUB_CLIENT_ID` / `_SECRET` (or the LinkedIn pair) empty to keep that method unavailable. After you set **both** values, restart the API — the public bitmap is frozen at boot. Removing a provider locks out people who only sign in with it.

Manually test: OAuth login, API key auth, avatar upload, and a reminder if you use scheduled jobs.

</Step>
