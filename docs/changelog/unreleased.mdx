## [Unreleased]

### ⚠️ Breaking

- Self-host: apply the new database migration before this app version. It rebuilds the `supported_locale` enum and adds French, Slovak, Spanish, Portuguese, Polish, Hungarian, Russian, Ukrainian, Dutch, Swedish, Danish, Norwegian, Finnish, Estonian, Latvian, Lithuanian, Italian, Romanian, Bulgarian, Serbian, Croatian, Slovenian, Greek, and Turkish.

### ✨ Added

- Webapp, mobile, and email: Bondery now speaks French, Slovak, Spanish, Portuguese, Polish, Hungarian, Russian, Ukrainian, Dutch, Swedish, Danish, Norwegian, Finnish, Estonian, Latvian, Lithuanian, Italian, Romanian, Bulgarian, Serbian, Croatian, Slovenian, Greek, and Turkish. Spanish is the Spanish of Spain. Portuguese is the Portuguese of Portugal. Norwegian is Bokmål. Serbian is Latin.
- Website: the Terms of Service page now carries the full agreement instead of a placeholder. It covers accounts, your ownership of your contacts, acceptable use, the free plan and Premium with its 15-day trial, the EU 14-day withdrawal right, AI assistants, self-hosting under AGPL-3.0, disclaimers, liability limits, and Czech law with the courts of Brno. The page links to the Privacy Policy for data handling.
- Plugins: one source, `llm-plugins/src`, now generates the Claude plugin folder and the OpenAI plugin folder. The OpenAI package is ready for a later directory upload. The listing sets the brand color, dark icons, `team@usebondery.com`, and no country limit. An onboarding skill introduces Bondery and the five jobs.
- Plugins: the Claude plugin manifest now sets `termsOfServiceUrl`, so the directory listing links the Terms of Service next to the privacy policy. The plugin README links both.
- Plugins: a Claude plugin for hosted Bondery ships `llm-plugins/claude`. It gives Claude five jobs: catch up before a meeting, get to know someone, save a conversation, find who to reach out to, and share a contact. Install the plugin, then connect and sign in. The plugin folder is content, not a workspace package. Its manifest carries the directory listing fields: icon, documentation link, support link, privacy policy link, and terms of service link.
- Branding: the website icon generator writes `llm-plugins/src/assets/icon.png`. The plugin builder copies that icon into the Claude and OpenAI packages, so it cannot drift from the brand.
- CI: `pnpm run check:llm-plugins` fails a pull request when the Claude plugin manifest drifts from the root version, when the license is not a regular AGPL-3.0 file, or when the bundle carries build files, env files, scripts, or secrets.
- CI: `publish-claude-plugin.yml` fast-forwards the `claude-plugin` branch to a production tag when `llm-plugins/claude` changed. The version field is ignored in that comparison, so a version-only release opens no directory review. RC tags never move the branch.
- Settings: a **date format** preference (follow language, month first, day first, or year first) independent of UI language. Calendar display uses pinned Gregorian Intl tags; storage and pickers stay ISO.
- Webapp and mobile: document direction follows the locale catalog (`dir`). Mantine `DirectionProvider` mirrors shell chrome. Map and graph canvases, phones, emails, and URLs stay `dir=ltr`. Contact names and note bodies use `dir=auto`. Mobile calls `I18nManager.forceRTL` only when resolved direction changes.

### 🔒 Security

- API: contact notes are now cleaned on the server before they are saved. Scripts, event handlers, and `javascript:` or `data:` links are removed, whichever client sent them (webapp, mobile, Chrome extension, API key, MCP, the assistant, or a Bondery ZIP import). Formatting, links, task lists, mentions, and dates are kept. Markdown input is now treated as text, so raw HTML typed in Markdown mode shows as text. Notes saved before this release are not rewritten. Notes are now limited to 20,000 characters on every write route, not only the notes route.
- API: file uploads are now capped while they stream, not after they load. A profile or contact photo over 5 MB gets a `413` with `validation_error` and the upload stops at the limit. Before, the API read up to 100 MB into memory first. The default cap for any upload is 5 MB. The import routes keep larger caps: vCard, LinkedIn export, Instagram export and Bondery ZIP 100 MB.
- CI: `pnpm run check:input-safety` fails when code writes contact notes without the sanitizer, or when the global upload ceiling grows. Two Biome rules, `biome/plugins/no-uncapped-multipart.grit` and `biome/plugins/no-raw-html-sink.grit`, fail the build on an upload read with no size cap and on a string written to the DOM as HTML.
- Self-host and hosted: the bundled Redis now requires TLS and a password. On the next `docker compose up`, a new one-shot `redis-secrets` service creates a random password and a TLS certificate in a new `redis-secrets` volume. Redis then accepts only TLS connections with that password, and the API checks the certificate. You do not need to change anything. Redis data stays. Compose now sets `BONDERY_PRIVATE_REDIS_URL` itself, so you can remove it from `.env`. If you pointed that Compose variable at your own Redis, run the API image alone instead (see the API container docs). In production, the API logs a warning at boot when Redis has no TLS or no password.
- Local development: `pnpm run start:redis` now starts Redis with TLS and a password, like the deployed stack. It creates the secrets in `.temp/redis-secrets` and binds Redis to `127.0.0.1` only (before, the port was open to your network). Run `pnpm run setup:dev` once to update an older `.env.local`, then `pnpm run env`.

### 🔄 Changed

- Docs: the MCP server page leads with the Claude plugin install and keeps the custom-connector steps for self-hosted API origins.
