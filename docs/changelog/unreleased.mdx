## [Unreleased]

### ✨ Added

- Webapp and API: Connect Claude Desktop, Cursor, and other MCP clients from **Settings → AI assistants**. Copy your MCP URL or an `mcp.json` snippet (`{apiBaseUrl}/mcp` on self-host) and sign in with OAuth 2.1 + PKCE. Cursor registers via RFC 7591; Claude Desktop uses CIMD. The MCP HTTP server is **2026-07-28 only**. Assistants can search contacts and read interactions, groups, tags, relationships, keep-in-touch, important dates, and a contact's groups/tags — and, if you grant Full access, create, update, and delete those records, including phones, emails, addresses, socials, date replace, group/tag memberships, and multi-participant interactions. Successful tool JSON matches REST (`{ contact }`, `{ group }`, `{ message }`, …). Deletes and sending a contact share email ask the host to confirm (Inspector 2026 / Claude). Clients that never retry elicitation cannot delete or send. You cannot delete your own contact card. Merge, import, photos, and billing stay in the Bondery app. The server sends usage instructions on initialize (search first, do not dump the address book). Prompts include catch-up, meeting brief, save contact, record interaction, reach out today, and organize a contact. Revoke access from the same card. API keys are not used on MCP. MCP clients never receive REST `api:access`.
- API: Creating a contact (web, mobile sync, chat, and MCP `create_contact`) can include phones, emails, socials, notes, and profile fields in the same call. Name-only create still works.
- API: `GET /contacts/:id/share-preview` lists which contact fields can be included in a share email. `POST /contacts/share` is unchanged.
- Chat and MCP: `get_contact_linkedin` reads LinkedIn bio, work history, and education already stored for a contact (same payload as `GET /contacts/:id/linkedin-data`).
- Chat: Contact, group, tag, and interaction lookups use the same API reads as REST and MCP.

### Breaking

- **Better Auth 1.7.6:** Upgraded from 1.7.1. The database migration drops `account.issuer` (Better Auth 1.7.3+ uses `(provider_id, account_id)` again). Hosted and self-hosted instances apply it automatically when the API container starts (`pre_start` / `release-migrate`). Rebuild `@bondery/db` and restart the API after generate so the Prisma client no longer selects `account.issuer`. Deploy the API and webapp together. Do not roll the API image back to 1.7.1 after this migration — social sign-in and account linking require the new schema.
- **OAuth plugin:** The API authorization server now uses Better Auth `mcp()` (CIMD + RFC 7591 DCR for MCP clients) instead of `oauthProvider()`. Deploy this API build together with the matching webapp. After migrate, OAuth clients store CIMD provenance (`client_discovery_id` and related columns). First-party webapp and Chrome extension clients stay REST-only; they are not MCP clients. DCR is limited to MCP resources and `mcp:*` scopes.

### 🐛 Fixed

- Webapp: `/login?error=` now shows a notification for OAuth and catalog failures (for example `internal_server_error`), not only magic-link verify codes. Copy comes from `getAuthUserFacingError`, never the raw server message.
- API: Cursor MCP connect accepts RFC 8252 loopback HTTP callbacks (`http://localhost:…/callback`) that Cursor registers as a web client. The DCR register limit is 30/min so reconnect retries are not 429'd.
- Webapp: OAuth consent for Cursor and other DCR assistants shows the registered app name instead of “Unknown application”.
- Webapp: Merge conflict resolution no longer shows an avatar picker when neither contact has a photo.
- Webapp: Instagram import instructions use nested bullets for Contacts and Followers instead of question marks.
- Webapp: OAuth consent and Settings → AI assistants describe MCP access as contacts and their data, not only interactions.
- Webapp: Merge no longer asks which avatar to keep when both contacts have the same photo bytes.
- API: Logging or updating an interaction now emits the contact's `lastInteraction` to mobile sync, matching other people writes.

### 🔄 Changed

- API and mobile sync: `PATCH /contacts/:id` and `contact.update` only accept writable contact fields (phones, emails, addresses, socials, notes, profile). Photo, myself, timestamps, and important dates are not update keys. Mobile important dates use `contact.replaceImportantDates` (same replace as `PUT /contacts/:id/important-dates`).
- Chat: In-app assistant tools now use the same names and catalog as MCP (`search_contacts`, `create_interaction`, `create_group_membership`, and the rest). Deletes and sending a share email still require confirmation in the chat thread; MCP still uses host protocol confirm. There is no myself tool — the assistant uses your contact card id with `get_contact`.
- API: MCP and in-app chat tool failures use the same nested error object as REST (`{ error: { type, code, message, request_id, doc_url } }`). MCP HTTP auth errors stay JSON-RPC.
- API: Missing contacts, groups, tags, and interactions now use resource-specific 404 codes (`contact_not_found`, `group_not_found`, `tag_not_found`, `interaction_not_found`) on REST, MCP, and chat — not generic `not_found`.
- Webapp: The app sidebar uses a Browse / Chats switch. Conversations live in the main sidebar (new chat, grouped by age). Drag the edge to resize; snap below the minimum width collapses to icons, with AI Assistant first when collapsed.
- Chrome extension: Saving a new person from a profile scrape uses the same contact-create path as the rest of the API, then photo, LinkedIn history, and the default import group.

### 📝 Documentation

- Contributing: [Inspect the MCP server](/docs/contributing/mcp) — run `pnpm run mcp:inspect` to authorize and call `{API}/mcp` with the 2026-07-28 MCP Inspector. The Inspector catalog is writable so Tools pagination and other session settings persist.

### 📦 Dependencies

- Tooling: pnpm 12.6.0 (`packageManager`). Docker image builds install the same pnpm. Minimum stays `>=12.4.0`.
