## [Unreleased]

### ⚠️ Breaking

- Self-host: the API serves HTTPS only, on port `26631`, the same number it used before. The plaintext listener on that port is gone, and the API does not start without its certificate (Compose provides it). If anything of yours calls `http://…:26631` (a monitor, a script, a proxy), change the scheme to `https://` on the same host and port, and trust the API CA (`deploy/bondery/scripts/api-ca.sh`). Running the API image alone behind a platform that forwards only plain HTTP to the container port no longer works; use the Compose stack.
- Self-host without Dokploy (host ports, no Traefik): copy the new `docker-compose.override.yml.example` over your `docker-compose.override.yml` before you upgrade. It turns off the new `traefik-transport` service, which needs a Traefik folder and stops the API from starting without it. The example also binds every stack port to `127.0.0.1` instead of all interfaces: the API on HTTPS `26631`, the storage gateway on HTTPS `8443`, and the webapp on `26632`. Put Caddy or nginx in front, with the ready-made configurations in `deploy/bondery/proxy/`. Export the API CA with `deploy/bondery/scripts/api-ca.sh`, and the storage CA plus the client certificate the gateway requires with `deploy/bondery/scripts/storage-ca.sh --client-dir <folder>`. See the new Reverse proxy page in the deployment docs.
- Self-host with your own Traefik (Coolify or other): set `BONDERY_INFRA_TRAEFIK_DYNAMIC_DIR` to the folder your Traefik's file provider watches, for example `/data/coolify/proxy/dynamic`. The `traefik-transport` service writes the API and storage transports there. Leave it empty on Dokploy.
- Self-host and hosted: the storage domain now answers only `GET`, `HEAD`, and `OPTIONS`. Public image reads work as before. Nothing in Bondery writes through that domain; uploads go through the API.

- Self-host: tools that connect to Postgres over an SSH tunnel (psql, pgAdmin, a BI tool) now need TLS. Export the CA with `deploy/bondery/scripts/postgres-ca.sh` and connect with `sslmode=verify-full`. Backups and restores with `docker compose exec db pg_dump` or `psql` work as before. If you pointed the Compose `DATABASE_URL` at your own database by editing the Compose file, use `docker-compose.external-postgres.yml` instead.
- Self-host: if `BONDERY_PUBLIC_POSTHOG_HOST` points to your own reverse proxy instead of PostHog, forward `/i/v1/analytics/events` and `/i/v1/ai/events` before you upgrade. The API and webapp now use `posthog-node` 6, which sends every server event to those capture v1 endpoints. Pass the `Authorization` header through, and allow request bodies up to 20 MB. Without that, PostHog answers `401`, and the batch is lost. Instances that send straight to PostHog need no change.
- Self-host: apply the new database migration before this app version. It rebuilds the `supported_locale` enum and adds French, Slovak, Spanish, Portuguese, Polish, Hungarian, Russian, Ukrainian, Dutch, Swedish, Danish, Norwegian, Finnish, Estonian, Latvian, Lithuanian, Italian, Romanian, Bulgarian, Serbian, Croatian, Slovenian, Greek, and Turkish.

### ✨ Added

- Website: the hero now leads with "Build stronger bonds". The subhead keeps the concrete offer, so the page still says what Bondery collects. "Everyone you know, in one place your AI can use" stays the claim for SEO titles and long-form copy.
- Website: the privacy section now shows a 3D padlock in the Bondery purple. The shackle swings closed once when you scroll to it, and the lock tilts toward a mouse pointer. With reduced motion it shows a still, closed lock. Browsers without WebGL keep the flat padlock.
- Website: the features section has a "Better than a spreadsheet" tile. It shows a plain gray table, then replaces it with the same three people as Bondery contacts, with a photo, a role, and when you met. With reduced motion it stays on the contacts. The hero subtitle now names the product: Bondery is a personal CRM.
- Webapp, mobile, and email: Bondery now speaks French, Slovak, Spanish, Portuguese, Polish, Hungarian, Russian, Ukrainian, Dutch, Swedish, Danish, Norwegian, Finnish, Estonian, Latvian, Lithuanian, Italian, Romanian, Bulgarian, Serbian, Croatian, Slovenian, Greek, and Turkish. Spanish is the Spanish of Spain. Portuguese is the Portuguese of Portugal. Norwegian is Bokmål. Serbian is Latin.
- Website: the Terms of Service page now carries the full agreement instead of a placeholder. It covers accounts, your ownership of your contacts, acceptable use, the free plan and Premium with its 15-day trial, the EU 14-day withdrawal right, AI assistants, self-hosting under AGPL-3.0, disclaimers, liability limits, and Czech law with the courts of Brno. The page links to the Privacy Policy for data handling.
- MCP: the server now serves the six Bondery skills (onboarding, catch up, get to know, remember, reach out, and share a person). An assistant that supports MCP skills can load them without the Claude or OpenAI plugin. The skills come from the same source as the plugins, `llm-plugins/src/skills`, so the three copies cannot drift.
- Plugins: one source, `llm-plugins/src`, now generates the Claude plugin folder and the OpenAI plugin folder. The OpenAI package is ready for a later directory upload. The listing sets the brand color, dark icons, `team@usebondery.com`, and no country limit. An onboarding skill introduces Bondery and the five jobs.
- Plugins: the Claude plugin manifest now sets `termsOfServiceUrl`, so the directory listing links the Terms of Service next to the privacy policy. The plugin README links both.
- Plugins: a Claude plugin for hosted Bondery ships `llm-plugins/claude`. It gives Claude five jobs: catch up before a meeting, get to know someone, save a conversation, find who to reach out to, and share a contact. Install the plugin, then connect and sign in. The plugin folder is content, not a workspace package. Its manifest carries the directory listing fields: icon, documentation link, support link, privacy policy link, and terms of service link.
- Branding: the website icon generator writes `llm-plugins/src/assets/icon.png`. The plugin builder copies that icon into the Claude and OpenAI packages, so it cannot drift from the brand.
- CI: `pnpm run check:llm-plugins` fails a pull request when the Claude plugin manifest drifts from the root version, when the license is not a regular AGPL-3.0 file, or when the bundle carries build files, env files, scripts, or secrets.
- CI: `publish-claude-plugin.yml` fast-forwards the `claude-plugin` branch to a production tag when `llm-plugins/claude` changed. The version field is ignored in that comparison, so a version-only release opens no directory review. RC tags never move the branch.
- Settings: a **date format** preference (follow language, month first, day first, or year first) independent of UI language. Calendar display uses pinned Gregorian Intl tags; storage and pickers stay ISO.
- Settings: the import dialogs for LinkedIn, Instagram, vCard, and Bondery JSON now finish inside the dialog. After an import, the last step lists the contacts that were added and offers **View contacts**, which opens the contact list, and **Close**, which stays in Settings. Before, the dialog closed and went to the contact list.
- Webapp and mobile: document direction follows the locale catalog (`dir`). Mantine `DirectionProvider` mirrors shell chrome. Map and graph canvases, phones, emails, and URLs stay `dir=ltr`. Contact names and note bodies use `dir=auto`. Mobile calls `I18nManager.forceRTL` only when resolved direction changes.

### 📦 Dependencies

- API: `@modelcontextprotocol/server` 2.0.0 to 2.4.0. The server now creates one `McpServer` per request, which the MCP route already did, and it serves the Bondery skills. No other code changed for the upgrade.
- All apps: about 120 minor and patch updates, among them Mantine 9.8, TipTap 3.34, better-auth 1.7.25, Fastify 5.12.8, TanStack Query 5.108, Prisma 7.10.1, and Expo SDK 58.0.26 with its matching React Native packages. Prisma stays on 7. React stays on 19.3.0, the version Expo SDK 58 pins.
- Tooling: Biome 2.6. It now checks Markdown and YAML as well, so the repo's own docs, skills, and workflow files are formatted. Locked upstream skills and generated mirrors are excluded. The stricter React rules led to small fixes in the webapp, mobile app, and `@bondery/mantine-next`: state is derived while rendering where an effect only copied it, and Reanimated shared values use `.set()`.
- Removed `@types/adm-zip`. `adm-zip` ships its own types.
- Held back on purpose: the Stripe SDK stays on 23.0.0, because 23.1.0 forces Stripe API version `2026-10-28.endive`. The docs stack stays on `fumadocs-core` and `fumadocs-ui` 16.16.2 with `fumadocs-mdx` 15.4.6 and `fumadocs-openapi` 12.5.4, because `fumadocs-core` 16.17 removed the `stringify` option that our docs Markdown converter uses.
- Webapp: `@mantine/tiptap` 9.8 imports `@tiptap/pm` without declaring it, so the workspace adds that peer through `packageExtensions`.
- All apps: i18next 27 and react-i18next 18. i18next 27 changes three defaults: `fallbackLng` is `false` until you set one, an empty translation falls back like a missing key, and a language code without a region is lowercased. Bondery already set `fallbackLng` and has no empty translation values, so only the type layer changed here. i18next 27 types `t()` as an overload list over tuple unions, so `LooseTranslateFn` is now declared with a bivariant method signature to keep the intentional casts for dynamic keys working. Translations tooling moves to i18next-cli 1.91.
- Webapp and website: `motion` 14. The removed APIs were the `13.4`-era internal ones restored only for `framer-motion` compatibility. Bondery imports `motion/react` only.
- Webapp: `supercluster` 9.1. The index is faster and smaller, and the package now ships its own types, so `@types/supercluster` is gone. Two type names changed shape: `ClusterFeature` and `PointFeature` are named exports that need the properties type argument.
- API and webapp: `posthog-node` 6. `captureException()` takes an options object, so the API reports the root cause with `{ properties }` instead of the positional distinct id. `before_send` is now `beforeSend`. The SDK sends events only through capture v1, keeps failed events for the next flush, and takes random bits for event UUIDs from `crypto.getRandomValues`.
- API: `@peculiar/x509` 3.1, which is ESM-only and resolves its internals through tsyringe, so `reflect-metadata` is now a direct dependency and imported before the library. Certificate generation and the expiry and issuer checks behave the same; the existing tests pass. v3 also rejects trailing bytes after a DER structure.
- Mobile: `@hookform/resolvers` 7. The breaking changes in 6 and 7 belong to the Effect, TypeBox and AJV resolvers. The mobile app uses `zodResolver` only, and Zod 4 support is unchanged.
- Mobile: `eas-build-cache-provider` 27. The `buildCacheProvider` config shape in `app.config.ts` did not change.

### 🔒 Security

- API: contact notes are now cleaned on the server before they are saved. Scripts, event handlers, and `javascript:` or `data:` links are removed, whichever client sent them (webapp, mobile, Chrome extension, API key, MCP, the assistant, or a Bondery ZIP import). Formatting, links, task lists, mentions, and dates are kept. Markdown input is now treated as text, so raw HTML typed in Markdown mode shows as text. Notes saved before this release are not rewritten. Notes are now limited to 20,000 characters on every write route, not only the notes route.
- API: file uploads are now capped while they stream, not after they load. A profile or contact photo over 5 MB gets a `413` with `validation_error` and the upload stops at the limit. Before, the API read up to 100 MB into memory first. The default cap for any upload is 5 MB. The import routes keep larger caps: vCard, LinkedIn export, Instagram export and Bondery ZIP 100 MB.
- CI: `pnpm run check:input-safety` fails when code writes contact notes without the sanitizer, or when the global upload ceiling grows. Two Biome rules, `biome/plugins/no-uncapped-multipart.grit` and `biome/plugins/no-raw-html-sink.grit`, fail the build on an upload read with no size cap and on a string written to the DOM as HTML.
- Self-host and hosted: the bundled Redis now requires a client certificate in addition to TLS and the password. A neighbor container that can reach Redis cannot connect with the password alone. On the next `docker compose up`, `stack-secrets` creates a private Redis CA and the certificates in new `redis-tls-*` volumes, keeps the current password, and Redis restarts once. Redis data stays. You do not need to change anything.
- Self-host: the stack supports only its bundled Redis. An external Redis is gone from the docs and from the deployment advice. The reason is not the TLS code, which still accepts a CA file and a client certificate pair: it is that most managed Redis cannot require a client certificate, so the supported path would weaken the rule from the previous entry. Compose also sets every Redis variable, so a value in `.env` never reached the API in this stack. Run the full Compose stack instead of the API image alone. The docs page for the API image is deleted.
- Local development: `pnpm run start:redis` now requires that client certificate. Run `pnpm run setup:dev` once so `.env.local` gains the cert and key paths, then restart Redis and the API.
- Self-host and hosted: every connection to Postgres now uses TLS that verifies the server, and the bundled Postgres refuses plaintext connections. On the next `docker compose up`, the `stack-secrets` service creates a private certificate authority and a server certificate in new `postgres-tls-*` volumes. Postgres restarts once with TLS on; your data stays. The API, the job queue, and migrations check the certificate and bind the login to the TLS session (channel binding). Existing databases are covered too: the new rule file replaces the one Postgres wrote when it was created, which allowed plaintext. The API logs the TLS version at boot, warns in production if TLS is turned off, and warns 90 days before the server certificate expires.
- Self-host: an external Postgres (RDS, Neon, Supabase, or your own) is now supported with `docker-compose.external-postgres.yml`. Set `DATABASE_URL` and, for a private CA, `DATABASE_SSL_ROOT_CERT_FILE` or `DATABASE_SSL_ROOT_CERT`. `DATABASE_SSL_MODE` defaults to `verify-full`. `sslmode=prefer` and `allow` are refused because they fall back to plaintext.
- Local development: `pnpm run start:postgres` now starts Postgres with TLS, like the deployed stack, and binds it to `127.0.0.1` only. It creates the CA in `.temp/postgres-secrets`. Run `pnpm run setup:dev` once, then `pnpm run env` and `pnpm run start:postgres`. Your local data stays.
- CI: `check:db-connections` fails when a Postgres connection does not take its TLS settings from `@bondery/db`, and the release smoke fails when Postgres accepts plaintext or an untrusted certificate.
- Self-host and hosted: object storage traffic is now encrypted. The API reaches the SeaweedFS gateway over HTTPS on port 8443 and checks its certificate, and the SeaweedFS nodes accept each other only over mutual TLS, so file chunks no longer cross the network in plaintext. Traefik also reaches the gateway over verified HTTPS for public image reads, and drops the `Cookie` and `Authorization` headers on that route: browsers sent the session cookie for your parent domain with every image request, and it no longer reaches SeaweedFS. On the next `docker compose up`, the `stack-secrets` service creates a private storage CA and a cluster certificate in new `storage-tls-*` volumes, and the SeaweedFS services restart once; your files stay. You do not need to change anything: Compose sets `BONDERY_PRIVATE_S3_ENDPOINT` and the new `BONDERY_PRIVATE_S3_TLS_CA_FILE`, and you can remove `BONDERY_PRIVATE_S3_ENDPOINT` from `.env`. Public image reads through your storage domain work as before. S3 tools that you point at the internal endpoint for backups need the storage CA. The gateway now runs as an unprivileged user and no longer opens its unused, plaintext Iceberg catalog port. The API warns in production when the S3 endpoint uses `http://`, and warns 90 days before the storage certificate expires.
- Self-host and hosted: the API and Traefik now identify themselves to object storage with their own client certificates, so the SeaweedFS gateway accepts only a caller the stack issued a certificate to. The gateway verifies those certificates against the storage CA, keeps a separate client certificate for Traefik, and refuses an unidentified client on port 8443. On the next `docker compose up`, the `stack-secrets` service adds two client certificates in a new `storage-tls-traefik` volume, and Compose sets `BONDERY_PRIVATE_S3_TLS_CERT_FILE` and `BONDERY_PRIVATE_S3_TLS_KEY_FILE` for the API. You do not need to change anything, and stored files stay. The API boot log line `Object storage connection security` now also reports `mutualTls: true`. If you back up with an S3 tool against the internal endpoint, that tool needs the CA and a client certificate from the storage CA; use the public storage domain for plain reads instead.
- Local development: `pnpm run start:seaweedfs` now runs SeaweedFS with TLS, like the deployed stack. It creates the CA and the client certificates in `.temp/storage-secrets`, and the API uses `https://127.0.0.1:8443` with its client certificate, published on `127.0.0.1` only. Run `pnpm run setup:dev` once, then `pnpm run env`, `pnpm run stop:seaweedfs`, and `pnpm run start:seaweedfs`. Your local files stay.
- Self-host and hosted: the webapp's server now calls the API over HTTPS. Page rendering and the webapp routes that proxy to the API carry access tokens, refresh tokens, and your data, and they no longer cross the shared Docker network in plaintext. The API now serves HTTPS only, on port `26631`, with TLS 1.3; its container healthcheck uses HTTPS too, and the plaintext listener on that port is gone. On Dokploy, Traefik now forwards public requests to that port over verified HTTPS as well, through a new one-shot `traefik-transport` service that writes the API and storage CAs into Dokploy's Traefik folder (or the folder in `BONDERY_INFRA_TRAEFIK_DYNAMIC_DIR`). Public URLs do not change. On a host without Traefik, copy the updated `docker-compose.override.yml.example`, which turns that service off. On the next `docker compose up`, the `stack-secrets` service creates a private API CA and a certificate in new `api-tls-*` volumes. You do not need to change anything: Compose sets the webapp's internal URL and CA. The webapp refuses to start when its CA file cannot be read, warns in production when its internal URL uses `http://`, and the API warns 90 days before its certificate expires.
- Local development: the API serves HTTPS only, like the deployed stack, on `https://127.0.0.1:26631` (loopback only). Portless forwards `https://api.usebondery.test` to it over HTTPS, and the webapp's server calls it directly. Run `pnpm run setup:dev` once: it updates `.env.local`, moves an old `http://…:26631` API URL to `https://api.usebondery.test`, and creates the API CA in `.temp/api-secrets` (`pnpm run api:secrets`). Then run `pnpm run env` and restart `pnpm run dev`. Re-register an `http://localhost:26631` OAuth callback as `https://api.usebondery.test/auth/callback/…`, and point MCP clients at `https://api.usebondery.test/mcp`.
- Local development: phones and emulators reach the API over Tailscale. `pnpm run dev:mobile-api` publishes it with `tailscale serve` at `https://<machine>.<tailnet>.ts.net:26631` (a public certificate) and stores that URL for the mobile app; `pnpm run env` hands it over. Web development keeps `https://api.usebondery.test` at the same time. The LAN-IP and `http://<tailscale-ip>:26631` setups are gone.
- CI: `check-compose` fails when the webapp's internal API URL is not the API's HTTPS listener with the API CA, and the release smoke fails when that listener accepts plaintext or a client without the CA.
- CI: a Biome rule, `biome/plugins/use-s3-client-factory.grit`, fails the build when API code creates an S3 client without `createS3Client()`, and `check-compose` and the release smoke fail when a SeaweedFS node accepts plaintext or a peer without the cluster certificate.
- API: the service-secret check for internal routes now compares the bearer token in constant time, so the response time does not leak the secret. No live route uses this check today. A Biome rule, `biome/plugins/no-unsafe-secret-compare.grit`, now fails the build when server code compares a secret, signature, or token with `==` or `===`.

### 🐛 Fixed

- Premium: the AI message period now follows your billing period. The usage counter resets when the plan renews, on the same date the subscription card shows, instead of a separate 30-day timer that started at signup. Your card used to name two different dates, one for the plan and one for the messages.
- Premium: a plan set to end at the next renewal no longer promises a message reset. When renewal stops, the reset date is hidden, because there is no next period.
- AI messages: every plan has a monthly allowance that resets each period, and the free plan now says so. Free keeps 5 messages per period and Premium keeps 300. Settings shows your usage and the reset date on every plan, and the chat alert names the date the allowance returns.
- AI messages: the free allowance is no longer affected by a past subscription. The counter used to keep a lifetime total that paid messages also added to, so an account that used its 300 Premium messages and cancelled arrived on the free plan with nothing left. Both plans now count the same monthly counter.
- Premium: the 300-message cap now applies. A Premium subscriber can no longer send more than 300 messages in a period; the check skipped the limit for paid plans.
- Self-host: apply the new database migration before this app version. It moves the AI reset column and the Stripe period bounds to `timestamptz` and points each paid account's reset at its current period end.
- Webapp: a page opened from the phone menu no longer arrives with scrolling disabled. The shell used to leave its viewport unable to scroll after the menu closed, so the page stayed stuck until a reload. Every page reached from the menu now scrolls normally. On a phone the menu still holds the page behind it while it is open.
- Webapp: the Instagram import and API key dialogs no longer change width partway through. The Instagram import grew to a much wider box on its last step, and the API key dialog narrowed when it showed the key. Each dialog now keeps one width from the first step to the last, like every other settings dialog.

### 🔄 Changed

- Webapp, website, and mobile: every component that builds a `className` now joins its parts with `cn()` from the [cn](https://github.com/shadcn-ui/cn) package, which resolves Tailwind conflicts so a class you pass to a component overrides the component's default. The mobile `joinClassNames` helper is gone. A Biome rule, `biome/plugins/use-cn-for-classname.grit`, fails the build on a template literal, a `+`, a `.join()`, `clsx`, `cx`, `classnames`, or `joinClassNames` inside `className`.
- Webapp settings: the import, export, and connected-account tiles are now built from one reusable card. The Bondery apps use a card with a logo, a title, and a button on the right; an installed app keeps its button as a disabled "Installed" state with a tooltip that says why, and the whole surface turns success green. They carry no status pill, because the button already names the state. The import and export tiles are one button, so the whole surface is tappable and keyboard reachable, with a description and a labelled link in the bottom-right corner. Every tappable card grows slightly on hover and squeezes on press. The grid fits as many cards as the panel allows, so a phone shows one and a wide page shows several, and longer translated descriptions no longer clip.
- Webapp settings: connected accounts are tappable tiles rather than a list. A linked provider fills with the success green, so the state reads before any label. The whole surface is the hit target: tap a linked provider to unlink it, or an unlinked one to connect. There is no separate action button and no per-row divider.
- Webapp fix page: a merge suggestion now reads top to bottom on a phone. The duplicate label sits first, then the two people centred one above the other with "merge with" between them, then the buttons in one row. On a wide screen the card is a single row: duplicate label, the pair, then the buttons. A long name now shortens with an ellipsis instead of pushing the buttons out of the card.
- Docs: the MCP server page leads with the Claude plugin install and keeps the custom-connector steps for self-hosted API origins.
- Developer experience: `pnpm run setup:dev` now moves `BONDERY_PUBLIC_STORAGE_URL` off the retired plaintext gateway and off the mutual-TLS gateway that refuses anonymous browser reads, and onto `http://127.0.0.1:8333`. A Tailscale name from phone testing is replaced too, because only a phone on the tailnet can resolve it. A deliberate custom URL is kept. Before this, an upgraded machine kept the stale value, and avatar and logo images failed to load in the browser.
- Developer experience: `pnpm run dev:remote-laptop` prepares a laptop browser for a remote editor session. It resolves this PC's Tailscale name, then writes a PowerShell script that points the `.test` hostnames at the PC and trusts the Portless CA for the laptop's Windows user. A remote editor renders its browser pane on the laptop, so trusting the CA on the PC was never enough, and the browser showed `ERR_CERT_AUTHORITY_INVALID` while `curl` on the PC succeeded. The CA is pinned by SHA-256, and the hosts block is replaced on each run instead of appended.
- API: a startup failure before Fastify exists now prints the error and exits with code `1`. TLS configuration, Redis, and object storage failures used to exit with code `0` and no message, so a container looked healthy after it stopped.
