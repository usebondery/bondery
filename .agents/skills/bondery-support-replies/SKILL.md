# Bondery support replies

Drafts stay in chat. The operator posts or sends them. Never comment on GitHub, never send email, never invent Stripe codes.

This is **not** marketing copy ([bondery-brand](../bondery-brand/SKILL.md)), UI microcopy ([bondery-ux](../bondery-ux/SKILL.md)), or product email templates ([bondery-emails](../bondery-emails/SKILL.md)).

## When to use

- Replying to a GitHub issue or discussion
- Drafting a support email (inbox, `team@usebondery.com`)
- Responding to App Store / Play reviews, social DMs, or similar 1:1 messages
- Answering a bug report, complaint, question, praise, or feature request from a real person

## Do not activate for

- Website, blog, ads, taglines → [bondery-brand](../bondery-brand/SKILL.md)
- In-product strings, empty states, i18n → [bondery-ux](../bondery-ux/SKILL.md)
- React Email templates, SMTP, Plunk → [bondery-emails](../bondery-emails/SKILL.md)
- Privacy/Terms wording, subprocessors → [bondery-legal](../bondery-legal/SKILL.md)
- Changelog / release notes → [bondery-changelog](../bondery-changelog/SKILL.md)

## Non-negotiables

1. **Draft in chat only.** Never post or send.
2. **Open with their name. Close with the answerer's name.** Default sign-off: **Sveetya**. Use another name only if the operator says so.
3. **User first.** Read and understand their problem. Do **not** recap it in the reply. They already described it. Answer them.
4. **Simple, direct, accurate.** Look up product or code facts when the question is about behavior. Do not invent ship dates, workarounds, or legal claims.
5. **No AI slop.** Ban the em dash. Ban filler: "I hope this helps", "Don't hesitate to reach out", "Great question", "I totally understand", "excited to", "leverage", "robust". Details: [references/voice.md](references/voice.md).
6. **YC founder bar.** Own mistakes. Be honest when we will not do something. Give a concrete next step.
7. **Invite more feedback in every reply**, especially negative. It helps make Bondery more delightful and useful for them.
8. **6 months of Premium is rare.** Offer only for unusually useful feedback or a serious frustration, never as a default thank-you. Point them to [team@usebondery.com](mailto:team@usebondery.com) so we know which account to credit. See [references/premium-offer.md](references/premium-offer.md).
9. **Public channels stay public-safe.** No other users' PII, no secrets, no internal Plane IDs.
10. **No regulatory boasts** ("GDPR compliant"). Flag legal or billing disputes for a human. See [bondery-legal](../bondery-legal/SKILL.md).

## Pre-ship checklist (drafted reply)

- [ ] Opens with their name; closes with Sveetya (or named answerer)
- [ ] Does not recap the problem they already described; answer is accurate (looked up if needed)
- [ ] No em dashes; no slop phrases
- [ ] Feedback invite present (negative welcome)
- [ ] Premium offer only if the bar is met; includes mailto to `team@usebondery.com`
- [ ] Public-safe if the destination is public
- [ ] Draft only; not posted or sent
