# ASD-100 (ASD-STE100 adapted)

Write agent replies, plans, summaries, comments, JSDoc, and technical documentation so a reader can parse each sentence once and get one meaning.

This file adapts ASD-STE100 Issue 9 **writing-rule categories**. It does **not** reproduce the official ~900-word dictionary. It is not certified STE.

Rule summary and copyright boundary follow [danyuchn/asd-ste100-skill](https://github.com/danyuchn/asd-ste100-skill) (`SKILL.md`, `references/writing-rules.md`).

Do not apply this register to published user-facing copy. That uses [orwell-hemingway.md](./orwell-hemingway.md).

## Scope

ASD-STE100 is free to obtain. It is not free to redistribute. Issue 9 states that reproduction in whole or in part needs written authority from ASD, except for listed member categories. This repo is not in those categories, so the dictionary stays out.

Apply **structural rules** as rules. Apply **lexical rules** as a direction: pick the plainest word and reuse it. Do not claim dictionary compliance.

When exact approved wording matters (aircraft maintenance), request the standard from the [official downloads page](https://www.asd-ste100.org/STE_downloads.html).

## Strict vs STE-flavored

**Strict** — procedures, comments, JSDoc, error strings in logs, implementation plans, `docs/api/`, `docs/deploy/`, `docs/contributing/`. Apply structural rules in full. Treat lexical rules as a hard consistency requirement inside the artifact (one name per concept).

**STE-flavored** — longer explanatory agent replies, PR descriptions, internal READMEs. Keep structural rules (length, active voice, no phrasal verbs, no semicolons, no marketing adjectives). Do not lock every synonym if that transplant would hide meaning.

User-facing changelog, blog, landing, and UI copy are **not** STE-flavored. They use Orwell-Hemingway.

## Structural rules

| Rule | Do | Don't |
|------|----|-------|
| Active voice | `The worker deletes the row.` | `The row is deleted by the worker.` — unless the actor is unknown |
| No phrasal verbs | `Remove the panel.` / `Start the job.` | `Take off the panel.` / `Spin up the job.` |
| One instruction per sentence | `Open the file. Read line 3.` | `Open the file and read line 3, then check if it matches.` |
| Sentence length | 20 words or fewer for procedures. 25 or fewer for descriptions | Long compound sentences |
| No semicolons | Split into separate sentences | Any semicolon |
| Noun clusters | 3 words or fewer (`sync pull cursor`) | 4+ (`mobile sync pull cursor handler assembly`) |
| No ellipsis | Keep subject, verb, and article | `Files not backed up will be lost` (which files?) |
| Keep modality | `The request may have failed.` | `The request failed.` when the source only said "may" |
| Paragraph limits | One topic. 6 sentences or fewer | Multi-topic paragraphs |
| Lists for sequences | Numbered or bulleted list for 3+ steps | A sequence buried in one sentence |
| Condition before action | `If lag exceeds 1,000, restart the worker.` | `Restart the worker if lag exceeds 1,000.` |

## Lexical rules — direction of travel

| Rule | Do | Don't |
|------|----|-------|
| One word, one meaning | One verb per action in the artifact (`check`, not `check`/`verify`/`confirm` for the same act) | Synonym rotation |
| One part of speech per word | Prefer noun `oil` + verb `apply` when both read well | The same word as noun and verb in one text |
| Verb, not noun | `Analyze the log.` | `Perform an analysis of the log.` |
| Domain terms | Keep necessary technical nouns and verbs. Define once if not common English | Jargon with no definition |

Bondery technical nouns stay exact: `person`, `group`, `tag`, `interaction`, `sync`, `outbox`, `pull`, `materializer`. Write API names, paths, Prisma models, and env vars in backticks with exact spelling.

## Simple tenses

Permitted: infinitive, imperative, simple present, simple past, simple future, past participle as adjective.

Exclude present perfect and other compound forms when the simple form carries the same meaning: `We received the report`, not `We have received the report`.

**Exception:** keep a compound form when it carries current relevance or a hedge (`The job has completed` vs `The job completed`; `may have failed`). Flag the departure only if someone asks for a rule table.

## Scan checklist

1. **Synonym rotation** — `the user` / `the customer` / `the client` for one thing. Pick one name.
2. **Hedge stacking** — `it is important to note that this may potentially help`. State the claim or delete it. Do not upgrade a real hedge to a fact.
3. **Nominalization** — `perform an analysis` → `analyze`.
4. **Marketing adjectives** — seamless, robust, powerful, cutting-edge. Delete, or replace with a measurement.
5. **Run-on sentences** — ideas joined by semicolons or stacked dashes. One idea per sentence.
6. **Soft phrasal verbs** — spin up, reach out, dive into, kick off. Use one plain verb.

## Process

1. Pick Strict or STE-flavored.
2. List the facts the reader must act on. Write each fact once.
3. Answer first. Put the conclusion in sentence one.
4. Walk sentence by sentence against the structural table and the scan checklist.
5. Preserve every fact, condition, number, and hedge. Do not add a cause the source did not state.
6. If the text has nothing to say, say so. Do not polish an empty paragraph.
