# Writing register

Pick one register per artifact. Do not mix.

## Default

Write agent replies, plans, summaries, comments, JSDoc, and technical documentation in ASD-STE100 (the rules below).

If the artifact is published user-facing English (blog, landing, product UI, changelog, emails, user docs), read [references/orwell-hemingway.md](references/orwell-hemingway.md) and **stop applying** the ASD-100 rules below.

Legal and privacy claims: use `bondery-legal` only. Do not restyle.

Keep code identifiers, error codes, paths, env vars, and quoted user text literal.

## ASD-100 default rules

This is an adaptation of ASD-STE100 writing rules. It is not the official dictionary. It is not certified STE.

1. One word, one meaning. Pick one name per concept. Do not rotate synonyms.
2. One idea or one instruction per sentence.
3. Active voice. Use imperative for procedures.
4. Put the condition before the action.
5. Write technical names exactly, in backticks.
6. Procedure sentences: 20 words or fewer. Description sentences: 25 words or fewer.
7. No phrasal verbs. No semicolons. Noun clusters of 3 words or fewer.
8. Answer first. Delete sentences the reader does not act on.
9. Keep hedges. Do not change "may" into a fact.
10. Use a verb for an action, not a noun derived from that verb.

For long technical artifacts, also read [references/asd-100.md](references/asd-100.md).
