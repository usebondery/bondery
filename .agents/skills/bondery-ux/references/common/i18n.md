# UI translations (i18n)

Do not hardcode user-facing strings in the webapp (or other clients that share `packages/translations`). All visible copy — labels, placeholders, buttons, notifications, aria labels, validation messages — belongs in translation files.

## Stack

- [i18next](https://www.i18next.com/) + [react-i18next](https://react.i18next.com/) (web) / i18next on mobile
- Tooling: [i18next-cli](https://github.com/i18next/i18next-cli) (`pnpm run i18n:status`)

## Locales

Supported locales live in `packages/schemas/locale/supported-locales.json`. Import `SUPPORTED_LOCALES` / `DEFAULT_LOCALE` from `@bondery/schemas/locale` (also re-exported by `@bondery/translations`). To add a language, read `bondery-i18n`. Do not copy this file's old locale list into a new language.

## Source of truth (strings)

`packages/translations/src/locales/{locale}/**` — one JSON file per namespace. Add every new key to **all** supported locales.

## Webapp hooks

Use the generated namespace hook from `@/lib/i18n/generated/hooks`:

```typescript
const t = useGroupsPageTranslations("AddGroupModal");
```

Server components use the matching generated function from `hooks.server`, such as `getGroupsPageTranslations()`.

Do not use `useWebTranslations()`, `getWebTranslations()`, or `t(key, { ns: "…" })`.

## Namespaces

Group keys by feature/page (e.g. `GroupsPage`, `ContactInfo`). Shared chrome lives in `common.json` (`actions.cancel`, `feedback.errorTitle`, etc.).

## Mobile

Use the generated namespace hook from the mobile generated hooks, such as `useMobileSettingsTranslations()`.

## Chrome extension

Use the generated namespace hook from the extension generated hooks, such as `useExtensionPopupTranslations("LoggedOut")`.

Generated hooks are rebuilt from `packages/translations/manifest.json` with:

```bash
pnpm run build -w @bondery/translations
```

Only genuinely runtime-defined keys may use `LooseTranslateFn`; keep that escape hatch local.

## Patterns

- Prefer small hooks for repeated copy (e.g. `useContactInfoLabels`, `useContactsTableCopy`) over duplicating `useMemo` blocks
- For modals opened outside React, set the title from the modal component via `modals.updateModal` once `t` is available

## CI

`pnpm run check:i18n` (or individual `check:i18n:*` scripts) — see root `package.json` / `.github/workflows/verify.yml`.

## Exceptions

Non-UI strings (logs, API field names, test IDs) and proper nouns/brand names that should not be translated.

When touching UI, wire strings to translations in the same change — do not leave English literals for a follow-up.

## Checklist

- [ ] New user-visible string added to every locale in `supported-locales.json`
- [ ] Correct namespace and key prefix used
- [ ] Every app uses its generated namespace hook — no generic namespace hooks or `t()` namespace options
- [ ] Dynamic keys use a local `LooseTranslateFn` cast only when the key is truly runtime-defined
- [ ] Generated hooks/types were rebuilt after locale or manifest changes
- [ ] `pnpm run check:i18n` passes if translations workspace touched
